04 — DIAGNOSEValid configuration · wrong outcome
Valid config. Wrong outcome. Three issues, explained.
ISSUE 1 · BGP ROUTE-MAP SCOPE
The route-map matches every prefix
match ip address prefix-list ANY (0.0.0.0/0 le 32) → local-pref 200
What it did
Payments and replication move to the 1 Gb/s path B along with the bulk traffic it was meant for.
How SevOne saw it
Flow top talkers on path B: replication 38%, payments 22%. BGP best path changed on 96 sessions (gNMI BGP data, Public Preview).
Fix
Match only the bulk-traffic prefix-list; keep payments on path A.
ISSUE 2 · SD-WAN SLA THRESHOLDS
The SLA class is far looser than reality
sla-class PAYMENTS-SLA latency 150 · loss 5
What it did
Payments normally run at 18 ms and 0.1% loss. At 63 ms and 2.1% the path still counts as compliant, so SD-WAN never steers away.
How SevOne saw it
SD-WAN tunnel monitoring TOR–MTL: latency 63 ms, loss 2.1%, jitter rising, while the policy reports the SLA met.
Fix
Derive SLA thresholds from SevOne baselines, e.g. 40 ms and 0.5% loss.
ISSUE 3 · NO OUTCOME CHECK
Success was defined as “config applied”
success criteria: syntax ✓ · lint ✓ · peers up ✓
What it did
Nobody checked utilization, latency, loss or flows on the new path, or what the BGP and SD-WAN changes did together.
How SevOne saw it
Baseline deviation at 09:23, two minutes after CHG0052418, correlated with the change and its actor.
Fix
Add a post-change outcome gate: query SevOne before a change is marked successful.
SevOne doesn’t read intent. It measures the outcome, and the outcome exposed all three.
